### Fixed

- `vibeqc.basis_optimization.drivers.optimize_scipy`, `optimize_minuit`, `optimize_bobyqa` and `optimize_dfols` passed a non-finite objective value (`np.inf` or `nan` for a failed SCF) straight to the optimiser, and `optimize_bobyqa`'s documentation said Py-BOBYQA treats `+inf` as a very poor point and steps away from it. It does not: Py-BOBYQA 1.5 stops at the first non-finite value with a linear-algebra error, and DFO-LS 1.6 stops with the same error for `inf` and, for `nan`, usually with `EXIT_EVAL_ERROR`. On random two-parameter quadratics with an infeasible disc that the raw run evaluated, a finite stand-in did better in all 77 Py-BOBYQA problems (median best value 10.6 raw, below 1e-20 with the stand-in) and all 61 DFO-LS ones (14.8 against 1.43). The four drivers now apply vibe-basis 0.14.0's rule, implemented locally because vibe-basis stays an optional extra: the optimiser sees the worst finite value seen plus `failure_margin=` (by default the spread of the finite values seen and at least 1e-3 of the worst), and DFO-LS sees the worst finite residual vector scaled to that sum of squares. `history` keeps the value the objective returned, the result's message counts the replacements, and a start point that is not finite ends the run unsuccessfully after one evaluation; raw MIGRAD used to spend 626 evaluations before giving up. `optimize_scipy` and `optimize_minuit` also report this run's evaluation count, and no longer need the objective to have an `n_calls` attribute.
